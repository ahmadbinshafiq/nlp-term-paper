## H1: Overlay as a View: Post-hoc Provenance from a Full Log

**Statement:** If the event log stores full prompts, model responses and tool payloads, then a claim-to-evidence graph rebuilt after the run by an LLM extractor reading only that log reaches provenance coverage and soundness within five percentage points of a graph captured inline during the run, so the provenance overlay is a derived view of the log rather than a separate architecture that must be paid for at run time.

**Prediction:** CONFIRMED if, on the same runs, the post-hoc graph's PCov (share of claims with a complete source-to-claim path) and PSnd (share of claim-source pairs the source actually supports) are within 5 points of the inline graph, and edge precision/recall against human labels exceeds 0.85, while storage is lower and extractor cost is a small fraction of generation cost. REFUTED if the post-hoc graph is more than 15 points behind on PCov or PSnd, or if the missing edges are concentrated in the 'observed' class (which passage was actually in context when a sentence was written), which would support Rasheed et al.'s claim that post-hoc verification cannot recover the chain. A separate 'final-checkpoint-only' input (answer plus retrieved-document IDs, no intermediate prompts) is expected to fall far behind both; if it does not, the log's intermediate content adds nothing for evidence tracing.

**Architectures:** log-primary (JSONL event log with full model and tool I/O, ActiveGraph-style content-addressed cache), provenance-overlay, inline variant (LEDGER/LongCite-style hooks recording context and citations as each sentence is produced), provenance-overlay, post-hoc variant (LLM extractor over the log), checkpoint-based, final-state-only (control: what survives if only the last snapshot is kept)

**Audit tasks:** evidence tracing, decision review (which source led to which claim)

**Metrics:** PCov and PSnd (Rasheed et al., AAR standard), AEff proxy: path length from claim to source, edge precision/recall of post-hoc vs inline graph, split by GRADE's observed / declared / inferred edge grades, ALCE citation recall and precision as a secondary output-level check, bytes per run per record type, extractor tokens and wall-clock per run

**Experiment:** Workflow: one research-QA agent (LangGraph or ActiveGraph) answering 100 questions from ALCE (ASQA/ELI5, fixed retrieval corpus so runs are reproducible) with search and read tools, writing a 5-10 sentence cited answer at temperature 0 with all model/tool I/O cached. Instrumentation, three records of the same run: (A) log-primary JSONL with full prompts, responses and tool payloads; (B) inline overlay: hooks record, at the moment each sentence is generated, which retrieved passages were in the context window and which were cited, giving observed claim-to-source edges; (C) final checkpoint only: answer plus retrieved-doc IDs. Post-hoc arm: an LLM extractor reads (A) or (C) and emits a claim-to-source graph. Ground truth: 150 claims from 30 answers hand-labelled for supporting passages; an NLI judge calibrated on AttributionBench scores the rest, with bootstrap confidence intervals. Measure PCov, PSnd, edge precision/recall by edge grade, path length, bytes, extractor tokens and time. 100 runs x 3 views, two extractor models, 3 seeds. Budget: roughly 100 generation runs plus 600 extraction calls, well under $150.

**Novelty:** Closest prior work: 'From Fluent to Verifiable' asserts that post-hoc verification cannot recover missing reasoning chains and that logs give insufficient traceability, but reports no measurement. 'GRADE' builds a post-hoc dependency layer from traces and explicitly says ground-truth reliance labels do not exist at scale. 'DRIFT/TELBench' shows a post-hoc claim ledger beats a plain judge but never compares it to an inline-captured graph. 'VeriTrail' builds a post-hoc DAG from stored intermediate outputs but does not contrast it with runtime capture. The literature sweep found no paper that measures how much of an inline-captured claim-evidence graph a post-hoc reconstruction from a complete log recovers. What is new: same runs, inline vs post-hoc vs final-snapshot, scored on claim-level metrics with human ground truth, plus the storage and compute cost of each, which directly tests whether the overlay is an architecture or a view.

**Related:** From Fluent to Verifiable: Claim-Level Auditability for Deep Research Agents; GRADE: Graph Representation of LLM Agent Dependency and Execution; Where Do Deep-Research Agents Go Wrong? Span-Level Error Localization in Agent Trajectories; VeriTrail: Closed-Domain Hallucination Detection with Traceability; LEDGER: Claim-to-Evidence Trace Graphs for Auditing LLM Agents; LongCite: Enabling LLMs to Generate Fine-grained Citations in Long-Context QA; Enabling Large Language Models to Generate Text with Citations; AttributionBench: How Hard is Automatic Attribution Evaluation?; Debugging Distributed Systems with Why-Across-Time Provenance; Workflow Cards: Structured Summaries of Workflow Executions Using Provenance Data; The Log is the Agent: Event-Sourced Reactive Graphs for Auditable, Forkable Agentic Systems

**Risks:** Inline instrumentation can change agent behaviour (an agent asked to cite writes differently); mitigate by capturing inline edges through hooks on what was in context, not by prompting the agent to cite. LLM extractor and NLI judge errors (about 20% on AttributionBench) can swamp a 5-point difference; hence the hand-labelled subset and confidence intervals. Internal 'reasoning in vector space' is unrecoverable by either arm, so ground truth must be defined as human-judgeable support, not the model's hidden reasoning. If the agent's context window holds all retrieved passages at once, 'observed' edges become trivial; use a retrieval budget so context differs per sentence.

## H2: Snapshots Suffice: State Diffs for Failure Localization

**Statement:** An LLM auditor that sees only per-step state snapshots shown as consecutive diffs (no prompts, no reasoning text) localizes injected faults at least as accurately as an auditor given the full event log, at a lower token cost, except for faults that change no state.

**Prediction:** CONFIRMED if step-level exact-match accuracy with checkpoint diffs is within 3 points of, or above, the full-log condition on state-changing faults (wrong tool, hallucinated argument, skipped precondition, stale data) while using at most half the tokens, and the full log wins only on state-silent faults (ignored observation, unsupported claim). REFUTED if the full log beats checkpoint diffs by more than 10 points overall, or if the diff condition's advantage disappears once the log is truncated to the same token budget (which would mean the effect is length, not state). A position-only baseline that guesses from injection position must score near chance for the result to count.

**Architectures:** checkpoint-based (structured agent state snapshotted after each step, viewed as diffs; CrewAI/OpenRath-style state, not the message list), log-primary (full JSONL event log: prompts, reasoning, tool I/O), provenance-overlay (typed step/artifact PROV graph without text bodies, as the third input)

**Audit tasks:** failure localization, execution reconstruction (secondary: can the auditor say what each step did)

**Metrics:** step-level exact-match accuracy and +/-2 tolerance (Who&When; LongRCA root-cause +/-k), agent-level accuracy (Who&When), silent-fault recall by fault type (trajectory-judge), tokens and wall-clock per audit, RF (record fidelity: share of required fields present per step) for each view

**Experiment:** Workflow: a tool-using support-desk agent with 7 deterministic tools over a synthetic backend (trajectory-judge style) or AgentCheck's MCP task; 40 base tasks that succeed at temperature 0 with cached I/O. Agent state is a structured object (task variables, scratchpad, retrieved records, pending actions); the message history lives only in the log. Fault injection: Who&When-Pro warm start; replay the successful prefix from cache, inject one of six fault types at step k, continue live; ground-truth step known by construction. 40 tasks x 5 positions = 200 faulted runs plus 40 clean controls. Three auditor inputs per run: (L) full event log; (C) state snapshot after each step rendered as consecutive diffs, no prompts or reasoning; (P) PROV graph of steps and artifacts without text. Same judge model and prompt; an extra condition truncates L to C's token length. Measure step exact match, +/-2, agent accuracy, recall by fault type, tokens per audit; run a position-only baseline to detect injection artifacts (CatchBench). Two judge models, 3 seeds; about 2,000 judge calls, under $100.

**Novelty:** Closest prior work: 'Seeing the Whole Elephant' (TraceElephant) varies record completeness (outputs only, full trace, replay environment) and finds large gains, but never uses state snapshots as the auditor's input. 'Crab' shows chat-only vs filesystem vs full-state snapshots differ for recovery correctness, not for auditing. 'ECHO' and 'TrajDebug' re-present the same log at several granularities but always from text, never from state. 'trajectory-judge' contrasts outcome-only with full trajectory. No paper asks whether a checkpoint sequence, the record the checkpoint family already keeps for recovery, is by itself an adequate audit record, nor separates faults by whether they leave a state footprint. That fault-type interaction is the new, decision-relevant result: it says which failures a checkpoint-only deployment can and cannot localize.

**Related:** Seeing the Whole Elephant: A Benchmark for Failure Attribution in LLM-based Multi-Agent Systems; Crab: A Semantics-Aware Checkpoint/Restore Runtime for Agent Sandboxes; Where Did It All Go Wrong? A Hierarchical Look into Multi-Agent Error Attribution; TrajDebug: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories; trajectory-judge: What Outcome-Only LLM Judges Miss on Agent Trajectories; Who&When Pro: Can LLMs Really Attribute Failures in AI Agents?; CatchBench: When Can an Agent Failure Be Caught?; OpenRath: Session-Centered Runtime State for Agent Systems; Auditable Agents

**Risks:** If the framework's state is just the message list (LangGraph default), the checkpoint condition collapses into the log; the student must design a structured state so the two records genuinely differ. Injected faults may produce unnaturally visible state changes (a corrupted field that screams), inflating the diff condition; use realistic perturbations and report the position-only baseline. Results may depend on the judge model (AgenTracer caution); use two judges. Diff rendering choices (JSON patch vs prose) are a hidden variable; fix one and report a second as a robustness check.

## H3: Shape over Substance: Record Format vs Record Completeness

**Statement:** With the auditor and token budget held fixed, changing how the same complete record is serialized (raw JSONL event log, chat transcript, typed per-step table, PROV graph) moves failure-localization and policy-compliance accuracy by more than deleting an entire content class (all reasoning text, or all tool outputs) from it.

**Prediction:** CONFIRMED if, in a factorial analysis, the format main effect on step-localization accuracy and compliance-decision accuracy is at least 1.5 times the completeness main effect (bootstrap CIs not overlapping), and the best format of a reduced record beats the worst format of the full record. REFUTED if completeness dominates (dropping tool outputs or reasoning costs more than any re-formatting gains) or if format effects vanish once token budgets are matched, which would mean earlier 'representation matters' results were really length effects. Either outcome tells the exposé whether architecture choice (what is stored) or serialization (how it is shown) is the lever.

**Architectures:** log-primary (raw JSONL and chat-transcript serializations), checkpoint-based (typed per-step table with state delta, the natural serialization of a snapshot sequence), provenance-overlay (PROV-JSON graph serialization)

**Audit tasks:** failure localization, policy compliance checking, decision review (secondary)

**Metrics:** step-level exact match and +/-2 (Who&When, LongRCA), compliance-decision accuracy against mechanical gold and SPDR (share of policies decidable from the record), TRAIL joint location-and-category accuracy, tokens per audit at matched budget, effect sizes from mixed-effects logistic regression with bootstrap CIs

**Experiment:** Reuse the 200 faulted runs from the snapshot study (or generate 120 fresh ones with the same warm-start injection). Design: 3 completeness levels (full; minus all reasoning text; minus all tool outputs but keeping tool names and arguments) x 4 formats (raw JSONL event log; chat transcript; typed per-step table with columns step, actor, tool, args, outcome, state delta; PROV-JSON graph). Every cell is a deterministic re-serialization of the same run, so no new agent runs are needed. Token budget matched by truncating to the smallest cell, with an unmatched variant reported separately. Auditor tasks: (1) name the faulty step; (2) decide 10 structural policies extracted AgentPex-style from the system prompt (gold from a mechanical checker on the full record). Add a CRE-style position control: faulty step early, middle or late. Fit a mixed-effects logistic model with run as random effect; report main effects, interaction and CIs. 12 cells x 200 runs x 2 tasks = 4,800 judge calls, about $100 with a mid-tier model; 3 seeds, two judges.

**Novelty:** Closest prior work: 'Holistic Evaluation and Failure Diagnosis of AI Agents' (Deepchecks) shows a 2.8x to 12x localization gap between whole-trace and span-wise judging; 'Where Did It All Go Wrong?' (ECHO) and 'TrajDebug' show multi-granularity views help; 'View-oriented Conversation Compiler' compiles one log into several views; 'Agent Flight Recorder' shows structured events beat grep. All vary presentation only, and 'Seeing the Whole Elephant' varies completeness only. None crosses the two to compare effect sizes, none matches token budgets, and none uses the three architectures' native serializations as the format levels. The new result is a direct estimate of which lever (storage architecture or serialization) matters more, which is exactly the assumption behind the exposé's architecture-first framing.

**Related:** Holistic Evaluation and Failure Diagnosis of AI Agents; Where Did It All Go Wrong? A Hierarchical Look into Multi-Agent Error Attribution; TrajDebug: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories; View-oriented Conversation Compiler for Agent Trace Analysis; Agent Flight Recorder: Tamper-Evident Audit Trails with On-Chain Anchoring for Long-Horizon Tool-Using Agents; Seeing the Whole Elephant: A Benchmark for Failure Attribution in LLM-based Multi-Agent Systems; Positional Failures in Long-Context LLMs: A Blind Spot in Reasoning Benchmarks; Willful Disobedience: Automatically Detecting Failures in Agentic Traces; TRAIL: Trace Reasoning and Agentic Issue Localization

**Risks:** Twelve cells invite multiple-comparison problems; pre-register the two main-effect contrasts and treat the rest as exploratory. Truncation to match tokens can itself delete the faulty step in long formats; truncate around the fault window symmetrically and report how often the fault is cut. Judge model idiosyncrasies (a model trained on chat transcripts may favour that format); use two judges from different families. The PROV-JSON format may be unfamiliar to the judge, confounding format with familiarity; include a short legend in every prompt.

## H4: Redaction Hits Checkpoints Hardest, Not Logs

**Statement:** Applying the same privacy treatment (field-level PII masking, and hash-only content as in the IETF Agent Audit Trail draft) to records of the same runs lowers structural policy decidability (SPDR) more for checkpoint snapshots than for the event log, and the event log loses no more than the provenance overlay, because snapshots serialize state as blobs that redaction must mask wholesale while logs and overlays keep policy-relevant fields (tool name, order, data class, approval flag) as separate typed fields.

**Prediction:** CONFIRMED if under hash-only recording SPDR stays at or above 0.9 for the log and the overlay but falls below 0.6 for checkpoints, and under field-level masking the checkpoint drop is at least twice the log drop. REFUTED if all three degrade by similar amounts (privacy-auditability tension is architecture-independent), or if the log degrades most (the intuitive expectation that free-text logs over-mask, and the direction the exposé's framing would predict). A second, sharper refutation: if policy classes flagged undecidable are the same set across architectures, then Nian's Proposition 1 (one missing field kills a policy class) operates at the schema level and the architecture choice is irrelevant to privacy cost.

**Architectures:** log-primary (JSONL event log with typed fields, hash-chained), checkpoint-based (per-step JSON state snapshots, LangGraph-style full state per step), provenance-overlay (PROV graph with typed nodes and edges; text bodies as attributes)

**Audit tasks:** policy compliance checking, execution reconstruction (secondary: ACR/RF under redaction), responsibility attribution (secondary: AC/ACD under pseudonymization)

**Metrics:** SPDR (share of structural policies decidable from the record), per architecture x redaction level (Nian et al.), ADL (audit detection latency) as secondary, ACR and RF (action recoverability, record fidelity) under each level, AC and ACD (attribution completeness and chain depth), fields lost per redaction level (empirical test of Proposition 1), RedAct-style verifier-field retention rate, bytes per run and redaction wall-clock

**Experiment:** Workflow: the same tool-using agent, with tools that read records labelled public / internal / PII and an approval step, so policies are meaningful. 40 tasks x 3 variants (compliant, violating, approval-missing) = 120 runs at temperature 0 with cached I/O, gold verdicts by construction. Records of each run: JSONL event log; per-step JSON state snapshots; PROV-JSON graph. Privacy levels applied uniformly with the same tool: raw; field-level PII masking (regex plus NER, as in Safe Observability); hash-only (every content field replaced by its SHA-256, structure kept). Policy set: 20 structural policies stratified into name/order-only ('tool X after tool Y'), approval-dependent ('X requires prior approval'), and content-dependent ('no external call after reading a PII-class record without sanitize'). Decider: a deterministic checker emitting comply / violate / undecidable (with an LLM checker as a robustness check). Measure SPDR per architecture x level x policy class, ACR/RF, AC/ACD, bytes, redaction time, and the exact fields each treatment removed. 120 runs x 3 records x 3 levels = 1,080 record instances; most computation is deterministic, so API cost is under $50.

**Novelty:** Closest prior work: 'RedAct' measures which verifier-critical fields survive trace rewriting but only on flat traces and never for policy checks. 'Auditable Agents' proves Proposition 1 (one missing field makes a policy class undecidable) and lists privacy-preserving mechanisms as an open problem with no measurement. The IETF 'Agent Audit Trail' draft mandates hash-only content without testing what remains checkable. 'Safe Observability' redacts PII in OTel pipelines but does not measure downstream audit loss. The LangGraph issue on checkpoint bloat shows full state is re-serialized per step but says nothing about redaction. The privacy gap note in the sweep found no redaction study for the checkpoint family at all. New: the first same-run, three-architecture, three-level redaction comparison scored with SPDR, and the first empirical test of Proposition 1, with a contrarian prediction that the checkpoint family, not the log, pays the privacy bill.

**Related:** Auditable Agents; RedAct: Redacting Agent Capability Traces for Procedural Skill Protection; Agent Audit Trail: A Standard Logging Format for Autonomous AI Systems; Safe Observability: A Framework for Automated PII Redaction from LLM Prompts in OpenTelemetry Pipelines; LangGraph checkpoint serialization produces 85% storage bloat and 37.8% token overhead with no opt-out path; Decision Trace Schema for Governance Evidence in Real-Time Risk Systems; DEMM-Bench: A Cross-Regime Benchmark for Agent-Runtime Governance-Evidence Sufficiency; Verifiable redactable audit log; ProvAbs: model, policy, and tooling for abstracting PROV graphs; Willful Disobedience: Automatically Detecting Failures in Agentic Traces

**Risks:** The policy set determines the answer: if every policy depends only on tool names and order, hashing costs nothing anywhere; the stratified policy classes are essential and should be fixed before running. The checkpoint result depends on serialization: a schema-aware JSON state lets the redactor mask fields, a pickle blob does not; run both variants and report them as a range rather than picking the one that confirms the claim. The redactor's aggressiveness is a free parameter; use one standard configuration and one stricter setting. Pseudonymization affects attribution (AC/ACD) more than decidability, so keep those metrics separate to avoid mixing effects.

## H5: State Is History: Quadratic Checkpoints vs Linear Logs

**Statement:** Because an LLM agent's state is mostly its accumulated history of model and tool outputs, a checkpoint store that saves the full state after every step grows quadratically in the number of steps, whereas an append-only event log recording the same fields grows only linearly, and delta-encoded checkpoints also grow linearly because they are a log in disguise.

**Prediction:** CONFIRMED if the fitted growth exponent b in bytes = a*n^b is >= 1.8 for per-step full-state checkpoints (LangGraph SqliteSaver) and <= 1.1 for the event log, the delta checkpoints, and the OTel span tree; if at n = 200 steps the full-state checkpoint store is >= 20x the log; and if the span tree is only 1-2x the log (it duplicates input+output per span). REFUTED if the checkpoint exponent is <= 1.2 or the size ratio at n = 200 is <= 3x, which would mean the checkpointer already de-duplicates or stores diffs and the storage axis does not separate the families. Classic theory (rr, ReVirt, Elnozahy's rollback-recovery survey) says logs are cheap because nondeterministic inputs ('determinants') are small relative to state; for agents the determinants ARE the state, so the classic gap is replaced by a linear-vs-quadratic gap.

**Architectures:** log-primary (append-only JSONL event log with content-addressed response cache; ActiveGraph or a hand-rolled equivalent), checkpoint-based, full state per step (LangGraph SqliteSaver), checkpoint-based, delta-encoded (JSON diff between consecutive checkpoints; DeltaBox-style), provenance-overlay, span tree (OpenInference/OTel GenAI spans in SQLite)

**Audit tasks:** execution reconstruction (storage is the price of being able to rebuild step k), evidence tracing (whether the record still holds full inputs/outputs at each step)

**Metrics:** bytes on disk after each step, per recorder, fitted growth exponent b with bootstrap CI, size ratio checkpoint/log at n = 50, 100, 200, marginal bytes per step at the tail, Record Fidelity RF (Nian et al.) held at 1.0 across recorders via a shared field schema, encoding overhead: same state serialized with pickle vs JSON (to separate serializer cost from growth)

**Experiment:** Workflow: one ReAct-style agent over four local tools (file search, calculator, mock web fetch, scratch memory) run for n in {10, 25, 50, 100, 200} steps on a fixed task list, 3 seeds each (15 runs). Model responses are generated once live (~1,000 calls) and cached, so every recorder replays the identical run at zero extra API cost. Recorders: (a) append-only JSONL log with content-addressed cache; (b) LangGraph SqliteSaver checkpoint per superstep; (c) delta checkpoint = JSON diff between consecutive checkpoints; (d) OpenInference span tree in SQLite. Normalize all four to one field schema (e.g., Agent Flight Recorder's eight fields) so RF = 1.0 everywhere and the comparison is fair. Measure bytes on disk after every step; fit bytes = a*n^b per recorder; report b with bootstrap CI, size ratios at n = 50/100/200, and marginal bytes per step. Separate encoding overhead (re-serialize an identical state with pickle vs JSON) from the growth exponent. Runs: 15 runs x 4 recorders = 60 recordings, no additional model calls. Optional sanity check: replay ActiveGraph's 671-event, 103-model-call diligence-pack fixture (offline, byte-deterministic) through all four recorders as a real-workload data point.

**Novelty:** Closest prior work: the LangGraph GitHub issue 'LangGraph checkpoint serialization produces 85% storage bloat' gives one 16-turn measurement against the filer's own commercial serializer, not against a log; 'Reasoning Provenance for Autonomous AI Agents' reports a self-described stylized 560 KB vs 25-130 KB per 10-step run with no growth curve; 'Efficient Fault Tolerance for Pipelined Query Engines via Write-ahead Lineage' shows KB lineage vs MB intermediates, but for query engines. None measures the growth exponent on an agent workflow, none states the 'determinants are the state' inversion of the rollback-recovery taxonomy, and none shows delta checkpoints collapsing into a log. The sweep found no paper that reports storage for the same run encoded three ways. New: first storage growth-curve comparison across all three families on one workflow with a normalized field schema, with a theory-derived exponent prediction.

**Related:** A survey of rollback-recovery protocols in message-passing systems; Engineering Record And Replay For Deployability: Extended Technical Report; ReVirt: Enabling Intrusion Analysis Through Virtual-Machine Logging and Replay; Event Sourcing; Efficient Fault Tolerance for Pipelined Query Engines via Write-ahead Lineage; LangGraph checkpoint serialization produces 85% storage bloat and 37.8% token overhead with no opt-out path; Reasoning Provenance for Autonomous AI Agents: Structured Behavioral Analytics Beyond State Checkpoints and Execution Traces; DeltaBox: Scaling Stateful AI Agents with Millisecond-Level Sandbox Checkpoint/Rollback; The Log is the Agent: Event-Sourced Reactive Graphs for Auditable, Forkable Agentic Systems; Agent Flight Recorder: Tamper-Evident Audit Trails with On-Chain Anchoring for Long-Horizon Tool-Using Agents; OpenInference Semantic Conventions; Auditable Agents

**Risks:** LangGraph internals may change or may already de-duplicate message objects across checkpoints, which would refute the hypothesis cheaply (still a publishable result, but a thin one). 'Same fields' fairness is the hard part: the log may store extra items (graph patches, cache entries) that the checkpointer does not, so a strict shared schema and a reported breakdown by field are essential. Serializer choice (pickle vs JSON) can dominate small-n numbers, so the exponent must be fitted on n >= 50. The result is about storage only; on its own it is thin for a semester and pairs naturally with hypothesis 2, which reuses the same recordings.

**Effort:** 4 weeks

## H6: Square-Root Law for Agent Checkpoints: Caching Moves the Optimum by 100x

**Statement:** The best spacing between checkpoints for an LLM agent follows the classic Young/Daly square-root law W* = sqrt(2*mu*C/r) (mu = mean steps between audit requests, C = cost to write and load one snapshot, r = cost to replay one step), so adding a content-addressed cache of model responses, which cuts r from seconds to milliseconds, should push the optimal interval from 'every step' to roughly every hundred steps, explaining why cache-less checkpointers like LangGraph snapshot every superstep and predicting that a cached log needs almost no checkpoints.

**Prediction:** CONFIRMED if (1) the empirically optimal interval W_emp (minimum mean time to reconstruct a uniformly random step k) lies within a factor of 2 of sqrt(2*mu*C/r) using directly measured C and r, in both the cached and uncached settings; (2) the cached optimum is at least 10x larger than the uncached optimum (theory says 30-100x for r_uncached ~ 3 s vs r_cached ~ 1 ms); (3) reconstruction of step k is byte-identical to the original (fidelity F = 1.0) for cached-log replay and for exact checkpoints, but F < 1 for uncached re-execution (Repair-or-Resample found unguided reruns reproduce failures only ~68% of the time). REFUTED if reconstruction latency shows no dependence on W, if W_emp is off from the formula by more than 3x, or if the cache shifts the optimum by less than 3x. Also refuted in spirit if strict cached replay is not byte-identical, which would undermine the 'replay is free' premise.

**Architectures:** log-primary with content-addressed cache (ActiveGraph or hand-rolled), plus a snapshotter of the log's projection at interval W (checkpoint+log hybrid), checkpoint-based without cache (LangGraph time-travel, which re-fires model calls after the restored checkpoint)

**Audit tasks:** execution reconstruction (rebuild state at step k), counterfactual analysis (fork at step k and continue)

**Metrics:** C: ms to write + load one snapshot (measured), r: ms to replay one cached event into the projection (measured), time-to-reconstruct step k (ms), averaged over random k, per interval W, W_emp vs predicted W* = sqrt(2*mu*C/r), model calls per reconstruction / per fork (0 for cached, k - k_ckpt for uncached), replay fidelity F (agrepl definition: fraction of reconstructions byte-identical to the original), fork cost: seconds and model calls to branch at k and run 5 further steps

**Experiment:** Reuse hypothesis 1's cached runs, plus synthetic long logs (10^4 and 10^5 events made by looping the cached workflow) so the millisecond constants are measurable above noise. Implement a snapshotter over the log's projection (in-memory state or graph) at interval W in {1, 5, 20, 100, infinity}. Measure C (write+load one snapshot) and r (replay one cached event) directly, 100 repetitions each, warm and cold cache. For each W draw 200 uniformly random audit targets k, reconstruct state at k (load nearest snapshot <= k, replay the remainder), record wall-clock ms; locate W_emp and compare to sqrt(2*mu*C/r) with mu = 1. Repeat uncached on LangGraph: reconstruct step k by time-travel from the checkpoint W steps earlier (re-firing model calls), W in {1, 5, 20}, 20 targets each (~500 live calls, ~$10-20), recording seconds, model calls, and fidelity F. Finally measure fork cost under each architecture: branch at k, run 5 live steps, count calls and seconds. Outputs: latency-vs-W curves, W_emp vs formula table, fidelity table, fork-cost table.

**Novelty:** Closest prior work: 'A first order approximation to the optimum checkpoint interval' and 'Checkpointing a la Young/Daly: An Overview' derive the law for HPC jobs; 'TARDIS' shows time-travel latency proportional to snapshot interval in managed runtimes; none has been applied to LLM agents, and none of the four papers in the student's folder cites them. 'The Log is the Agent' names 'replay cost grows with log length, we do not yet provide checkpointing' as an open limitation without numbers; 'Knowledge-Based Zero-Replay Debugging' models counterfactual cost as O(T x |F| x N) model calls but never asks about checkpoint interval. New: first transfer of the square-root law to agents with the response cache as the independent variable, giving a mechanistic explanation for why cache-less frameworks checkpoint every superstep and a quantitative rule for when a log-primary system should add snapshots.

**Related:** A first order approximation to the optimum checkpoint interval; Checkpointing à la Young/Daly: An Overview; TARDIS: Affordable Time-Travel Debugging in Managed Runtimes; In Search of an Understandable Consensus Algorithm (Extended Version); Lineage Stash: Fault Tolerance Off the Critical Path; Use time-travel (LangGraph documentation); The Log is the Agent: Event-Sourced Reactive Graphs for Auditable, Forkable Agentic Systems; Deterministic Replay for AI Agent Systems; Repair or Resample? **Risks:** The measured constants are milliseconds, so OS file caching and Python overhead can swamp them; mitigate with many repetitions, cold/warm runs, and the synthetic 10^5-event logs. If the projection (fold) is trivially cheap, reconstruction latency may be flat across W for realistic run lengths, making the checkpoint question moot for short runs (itself a useful finding, but weaker). Young/Daly assumes audit targets are uniformly spread, whereas real auditors mostly inspect the end of a run; report both uniform and end-weighted targets. Uncached re-execution costs real money and is nondeterministic. Per 'Statistical Independence Aware Caching', a cached prefix must not be served where the counterfactual needs a fresh sample, so the fork test must state which steps are replayed and which are re-sampled.

**Effort:** 5 weeks

## H7: Why-Provenance Ceiling: Post-Hoc Overlays Over-Approximate, Counterfactuals Need Re-Execution

**Statement:** A provenance overlay reconstructed after the fact from an agent's log can only recover causal over-approximations of a black-box model call (every input in the prompt looks like a source), so it will score high on evidence-tracing recall but low on precision compared with an overlay captured during generation, and neither overlay can answer 'would this claim change if that source were removed' as accurately as actually re-running the agent from a cached fork, because that question needs how-provenance, which a model call does not expose.

**Prediction:** CONFIRMED if the post-hoc (log-derived) overlay reaches source-attribution recall >= 0.9 but precision <= 0.4 (theory: precision ~ true sources / retrieved chunks in the prompt, e.g. 1-2 of 8), the inline overlay reaches precision >= 0.8 (VeriGraph reports 87.6% grounding), and agreement between overlay-simulated counterfactual answers and observed re-execution is <= 0.75 for both overlays. REFUTED if the post-hoc overlay's precision is within 10 points of the inline overlay (LLM reconstruction recovers why-provenance fine), or if simulated-vs-observed counterfactual agreement is >= 0.9 (how-provenance is not needed in practice). Provenance theory ('Why, How, and Where'; wat-provenance) predicts the split; the Replay Gap and Repair-or-Resample results predict the simulated ceiling.

**Architectures:** log-primary (event log with cached responses; source of the fork oracle), provenance-overlay, inline (claim-evidence graph emitted during synthesis, LongCite/VeriGraph/LEDGER style, stored as PROV-DM), provenance-overlay, post-hoc (LLM-reconstructed from the log alone, GRADE/AuthGraph style), checkpoint-based fork as the re-execution oracle (restore at retrieval step, delete the source, continue live)

**Audit tasks:** evidence tracing (which source supports which claim), counterfactual analysis (would the claim survive without source s), decision review (which retrieved evidence actually drove the final claims)

**Metrics:** source-attribution precision and recall vs human labels (AIS protocol), Provenance Coverage PCov and Provenance Soundness PSnd (Rasheed et al.), Audit Effort AEff proxy = provenance path length, simulated-vs-observed counterfactual agreement (fraction of (claim, source) pairs where the overlay's predicted survival matches actual re-execution), model calls per counterfactual query (0 simulated vs ~8 observed), judge calibration: F1 of the NLI/LLM support judge on AttributionBench

**Experiment:** Agent: a small retrieve-then-write research agent over a frozen local corpus (ALCE-style; 30 questions from DeepResearch Bench or ExpertQA with ~50 pre-fetched documents each), 8 retrieved chunks per prompt, ~10 steps per run, run once with cached responses (~300 calls). Records: (a) event log; (b) inline overlay: the agent emits per-claim citations during synthesis, stored as a PROV-DM claim-evidence graph; (c) post-hoc overlay: an LLM builds the same graph from the log alone. Ground truth: 150 claim-source pairs labelled by the student under the AIS 'according to P, s' test; an NLI/LLM judge calibrated on AttributionBench scores the remainder, with confidence intervals. Measure per overlay: attribution precision/recall, PCov, PSnd, AEff path length. Counterfactual test: for 40 (claim, source) pairs, remove the source and (i) ask each overlay whether the claim survives (simulated, zero replay), (ii) fork the log at the retrieval step with the source deleted, replay the cached prefix, run live from there (~40 x 8 = 320 calls), and check whether the claim survives (observed). Report simulated-vs-observed agreement and model-call cost. Runs: 30 base runs x 3 records + 40 forks.

**Novelty:** Closest prior work: 'Provenance in Databases: Why, How, and Where' and 'Debugging Distributed Systems with Why-Across-Time Provenance' give the theory (why-provenance suffices for evidence tracing, how-provenance is needed for counterfactuals, exact provenance cannot be recovered post hoc from a black box) but never touch LLMs. 'GRADE' grades overlay edges as observed/declared/inferred and explicitly says ground-truth reliance labels do not exist; 'VeriGraph' is inline only; 'From Flat Logs to Causal Graphs' (CHIEF) simulates counterfactuals and validates only against its own replay oracle; 'From Fluent to Verifiable' argues post-hoc verification cannot recover reasoning chains but measures nothing; the survey 'From Agent Traces to Trust' lists inline-vs-post-hoc fidelity as an open problem. New: inline overlay, post-hoc overlay, and observed re-execution compared on the same runs with a precision/recall split and a counterfactual ceiling both derived from provenance theory.

**Related:** Provenance in Databases: Why, How, and Where; Provenance Semirings; Debugging Distributed Systems with Why-Across-Time Provenance; Resilient Distributed Datasets: A Fault-Tolerant Abstraction for In-Memory Cluster Computing; GRADE: Graph Representation of LLM Agent Dependency and Execution; VeriGraph: Towards Verifiable Data-Analytic Agents; PROV-AGENT: Unified Provenance for Tracking AI Agent Interactions in Agentic Workflows; From Fluent to Verifiable: Claim-Level Auditability for Deep Research Agents; From Agent Traces to Trust: A Survey of Evidence Tracing and Execution Provenance in LLM Agents; Aligning Provenance with Authorization: A Dual-Graph Defense for LLM Agents; From Flat Logs to Causal Graphs: Hierarchical Failure Attribution for LLM-based Multi-Agent Systems; The Replay Gap: Static Evaluation of Model Switching in LLM Agents Scores the Wrong World; Measuring Attribution in Natural Language Generation Models; AttributionBench: How Hard is Automatic Attribution Evaluation?; LongCite: Enabling LLMs to Generate Fine-grained Citations in Long-Context QA; Enabling Large Language Models to Generate Text with Citations

**Risks:** Needs human labels for ~150 claim-source pairs (roughly 10-15 hours of the student's time) and an LLM judge with ~20% error (AttributionBench), so all metrics need confidence intervals and a human-checked subset. The inline overlay's quality depends on the model's citation behaviour; a model that cites everything would blur the predicted precision gap. Observed counterfactuals are themselves stochastic, so each fork should be run 2-3 times and 'claim survives' scored by majority. The 'black box' premise could be challenged by attention-based attribution, which is out of scope and should be stated as such. This is the heaviest of the four and only fits a semester if the corpus and agent are kept small.

## H8: Compaction Keeps the Final State, Kills the Lifecycle

**Statement:** Compacting an agent's record so that only the latest value per object survives (Kafka-style) or only a summary of the prefix survives (context-compaction style) preserves audits over the final state but destroys audits over the lifecycle, so lifecycle coverage (LPC), sequence-policy decidability (SPDR), and localization of transient faults will fall roughly in proportion to the share of retries and overwrites in the run, while action recoverability (ACR) and final-state policy checks stay near 1.0.

**Prediction:** CONFIRMED if, at a retry/overwrite share of rho = 0.3, key-based compaction yields LPC <= 0.6 and sequence-policy SPDR <= 0.5 (many policies flip to 'undecidable', as Nian's Proposition 1 predicts when fields vanish) while ACR >= 0.95 and final-state SPDR = 1.0; if transient-fault step-localization accuracy drops by >= 30 points while terminal-fault accuracy changes by <= 5 points; and if storage reduction tracks rho (compaction saves roughly the overwritten share). REFUTED if LPC >= 0.85 or sequence-policy SPDR >= 0.85 at rho = 0.3 (e.g., because retries create new keys rather than overwrites, so nothing is lost), or if transient and terminal faults degrade equally (the split predicted by 'keep latest per key' does not exist).

**Architectures:** log-primary (uncompacted event log as the reference), log-primary under Kafka-style keep-latest-per-key compaction, log-primary under Raft-style prefix snapshot (drop events before step s, keep state), log-primary under LLM prefix summarization (agent context-compaction style), checkpoint-based, latest-state-only (AutoGen save_state / CrewAI latest-row style) as the natural endpoint of compaction

**Audit tasks:** execution reconstruction (lifecycle phases: retries, fallbacks, approvals), policy compliance checking (final-state policies vs sequence policies), failure localization (transient vs terminal injected faults)

**Metrics:** Lifecycle Coverage LPC and Gap Burden GB (Nian et al.), Action Recoverability ACR and Record Fidelity RF (Nian et al.), Structural Policy Decidability SPDR split into final-state policies and sequence policies, reporting comply/violate/undecidable, step-level localization accuracy with a fixed LLM judge (Who&When protocol), separately for transient and terminal faults, storage reduction (bytes compacted / bytes original), retry/overwrite share rho as the independent variable

**Experiment:** Start from hypothesis 1's recorded runs (n = 50 and 100 steps). Inject lifecycle events at share rho in {0, 0.1, 0.3, 0.5}: tool timeouts followed by retries, model fallbacks, and overwritten scratch-memory keys; plus two fault types with known positions: transient (wrong tool result at step j, corrected at j+2, but a side effect already fired) and terminal (wrong result propagates to the end). Apply three compaction operators to each log: (i) Kafka-style keep-latest-per-key; (ii) Raft-style prefix snapshot at s = n/2; (iii) LLM summary of the prefix. Add an AutoGen-style latest-state-only checkpoint as the endpoint. Write 10 final-state policies ('no forbidden tool in the final plan') and 10 sequence policies ('approval precedes execution', 'at most two retries'). For each record compute LPC, GB, ACR, RF, SPDR per policy class, storage reduction, and step-localization accuracy with one fixed LLM judge for transient vs terminal faults. Runs: 2 lengths x 4 rho x 3 seeds = 24 base runs x 5 record variants = 120 records; judge calls ~120 x 2 faults = 240, all on cached runs, so API cost is a few dollars.

**Novelty:** Closest prior work: 'Kafka Log Compaction', Raft Section 7, and Fowler's 'Event Sourcing' state the loss of superseded history qualitatively; 'Beyond Compaction' argues summarization destroys causal structure but measures only task accuracy; Temporal's 51,200-event cap and Continue-As-New are never evaluated for audit loss; 'Auditable Agents' defines LPC, GB, and Proposition 1 but never computes them under compaction (its own limitations say no end-to-end audit exists); 'TrajDebug' separates resolved from terminal errors but does not vary the record. The sweep notes state explicitly that no one measures how snapshotting or compaction degrades audit properties. New: first measurement of which audit tasks survive which compaction operator, with a theory-derived prediction that loss is proportional to the overwrite share and that transient faults are the casualties.

**Related:** Kafka Log Compaction; In Search of an Understandable Consensus Algorithm (Extended Version); Event Sourcing; Events and Event History (Temporal documentation); Beyond Compaction: Structured Context Eviction for Long-Horizon Agents; Inside the Scaffold: A Source-Code Taxonomy of Coding Agent Architectures; Auditable Agents; Managing State — AutoGen; Flows (CrewAI documentation); TrajDebug: Tracing Error Lifecycle to Identify Critical Failures in Long-Horizon Agent Trajectories; Safe to Resume? Breaking Execution Continuity of Agent Execution via Rollback; Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems

**Risks:** Injected retries and overwrites may be artificial; the design should mirror real patterns (timeouts, fallbacks) and state this limitation. Sequence policies must be written so they are decidable on the full log, otherwise 'undecidable' is trivially inflated. The LLM judge for localization is noisy (11-28% step accuracy on human-labelled data), so use injected faults with known positions and report the judge's baseline on the uncompacted log. The summarization operator depends on the summarizing model and prompt; fix both and treat it as one point, not a family. Depends on hypothesis 1's recordings, so it is best run as a follow-on or as the second half of a combined H1+H4 project.

**Effort:** 5 weeks

## H9: The compaction curve: what an event log loses once it starts snapshotting

**Statement:** If an append-only agent event log is compacted by saving a full snapshot of the projected state every S events and deleting the events before it, the time to rebuild the state at any step k falls roughly in proportion to S, but an auditor's accuracy at locating a fault injected before the last kept snapshot, and the ability to fork (branch and re-run) the run at that point, drop to the level of having no record at all - so no snapshot interval cuts replay time without cutting audit coverage.

**Prediction:** Confirmed if (a) replay time to step k scales with the distance from the last snapshot (k mod S) rather than with k, and (b) step-localization accuracy and fork success for faults located before the last kept snapshot fall to within ~5 points of a no-record baseline, while tasks that only need the latest state (structural policy checks on the final configuration, review of the final decision) are unchanged. Refuted if localization accuracy for pre-snapshot faults stays within ~10 points of the full-log condition: that would mean the provenance pointers that ActiveGraph keeps inside every graph object ('caused by event / behavior / model call') survive the snapshot and preserve enough evidence, so compaction is far cheaper for audit than the log-primary literature assumes.

**Architectures:** log-primary (ActiveGraph, S = infinity: full event log), checkpoint-plus-log hybrids (ActiveGraph store with a snapshot every S events and the older events deleted, S in {256, 64, 16, 4}), checkpoint-based (per-step state snapshots only, no events kept - the LangGraph-style extreme, where events must be inferred by diffing consecutive snapshots)

**Audit tasks:** execution reconstruction, failure localization, counterfactual analysis, policy compliance (as a control task expected not to degrade), decision review (as a control task expected not to degrade)

**Metrics:** Replay wall-clock seconds to reach the state at step k (TARDIS-style time-travel latency), Bytes on disk per condition, ACR and RF from Auditable Agents (share of policy-relevant actions recoverable; share of required fields per action), Step-localization exact match and root-cause +/-5 accuracy from LongRCA Bench, by one fixed LLM judge, Fork success rate and prefix-match replay-validity fraction from The Replay Gap, SPDR from Auditable Agents (share of structural policies the record can decide) on six policies

**Experiment:** Workflow: ActiveGraph's shipped diligence-pack example (671 events, 103 cached model calls; runs offline and byte-deterministic, so replays cost nothing). Instrumentation: a small compaction layer on the ActiveGraph store that every S events serializes the projected graph to JSON and deletes earlier events, S in {inf, 256, 64, 16, 4}, plus a per-step-snapshot-only condition (state after every event, no events kept) standing in for LangGraph-style checkpointing. Ground truth: 30 single-point faults made by forking at event k, corrupting one cached tool or model response (wrong number, dropped document, contradicting fact) and letting the run continue, with k spread evenly over the run, so the faulty step is known by construction (the Who&When Pro recipe). Measurements per condition x fault: seconds to rebuild state at the fault step; bytes on disk; whether a fork at k minus Delta (Delta in {1, 10, 100}) can start and replays validly; ACR/RF by field checklist; one fixed LLM judge (same model, prompt and token budget) asked for the faulty step, scored exact and +/-5; SPDR on six structural policies. Runs: 6 conditions x 30 faults = 180 records, each judged 3 times (~540 judge calls); replays and forks run locally.

**Novelty:** The Log is the Agent names compaction as the missing piece ('a million-event run is replayed in full today') and reports no empirical evaluation. Young's 1974 note and the Young/Daly overview give the checkpoint-interval-versus-replay-time law, and TARDIS measures snapshot interval against time-travel latency, but for HPC jobs and managed runtimes, never for an agent record and never against audit tasks. Kafka log compaction and Raft Section 7 say qualitatively what is lost when a prefix is dropped; Beyond Compaction argues summarization destroys causal structure but measures task accuracy, not auditability. No paper measures audit-task degradation as a function of snapshot interval on an LLM-agent record, and none tests whether a snapshotted graph that carries provenance pointers rescues failure localization. The contribution is modest but real: it turns 'log versus checkpoint' from two boxes into one measured curve.

**Related:** The Log is the Agent: Event-Sourced Reactive Graphs for Auditable, Forkable Agentic Systems; A first order approximation to the optimum checkpoint interval; Checkpointing a la Young/Daly: An Overview; TARDIS: Affordable Time-Travel Debugging in Managed Runtimes; In Search of an Understandable Consensus Algorithm (Extended Version); Kafka Log Compaction; Beyond Compaction: Structured Context Eviction for Long-Horizon Agents; Events and Event History (Temporal documentation); Event Sourcing; Lineage Stash: Fault Tolerance Off the Critical Path; LongRCA Bench: Diagnosing Responsible Roles and Root Causes in Long-Horizon Agent Failures; Who&When Pro: Can LLMs Really Attribute Failures in AI Agents?; LangGraph checkpoint serialization produces 85% storage bloat and 37.8% token overhead with no opt-out path; Auditable Agents

**Risks:** ActiveGraph's projected graph may embed event references, so truncation must explicitly strip event bodies and the paper must state exactly what a snapshot contains. The diligence run may be too short to show a clear curve (mitigation: chain three runs or loop the workflow to a few thousand events). LLM-judge noise at the +/-5 tolerance (mitigation: three judge repeats, confidence intervals). Injected faults may be spotted from formatting artifacts rather than evidence, as CatchBench warns (mitigation: corrupted values must be plausible and the judge must be tested on clean runs for false positives).

## H10: Cached-prefix fork versus re-fire fork: which counterfactual is honest, and when does the log stop being enough?

**Statement:** For a single injected fault at step k, a log-primary fork that replays the recorded prefix from cache and re-runs only the suffix reaches the same repair verdict (does fixing step k flip the run to success?) as a checkpoint-restore fork that re-fires model and tool calls, at less than half the model-call cost, as long as tools are side-effect-free - but once a tool keeps state outside the record (a file or table the run mutates), the log-primary fork's agreement with an environment-restoring fork drops below 70%.

**Prediction:** Confirmed if, with stateless tools, the log fork and the checkpoint fork agree on the flip verdict in at least 90% of faults while the log fork uses at most 50% of the model calls, and, with a stateful tool, the log fork's agreement with the checkpoint-plus-environment fork falls below 70% while the checkpoint-plus-environment fork itself stays at or above 90% agreement with a full fresh re-execution. Refuted if (a) agreement is already low with stateless tools, meaning re-fired suffixes are as good as cached ones and the 'cheap honest fork' claim buys nothing for attribution, or (b) the log fork stays at or above 90% even with stateful tools, meaning recorded tool responses are enough and environment snapshots are unnecessary for audit-grade counterfactuals.

**Architectures:** log-primary (ActiveGraph fork: shared prefix served from the content-addressed cache, live calls only after k), checkpoint-based (LangGraph time travel: get_state_history plus update_state fork, which re-fires model and tool calls after k), checkpoint-based with environment snapshot (LangGraph fork plus restoring a copy of the SQLite/file state at step k - the 'chat + filesystem' rung of Crab's ladder)

**Audit tasks:** counterfactual analysis, failure localization (verified by intervention, DoVer / Causal Agent Replay style), execution reconstruction (prefix fidelity as a by-product)

**Metrics:** Flip rate / Causal Responsibility Score from CausalFlow (does any of K corrective alternatives at step k flip the outcome), Verdict agreement between fork types (paired, per fault), Failure-reproduction rate of an unguided rerun (SymTrace's 67.97% reference point), First-divergent-action index and normalized post-fork action edit distance from The Replay Gap, Model calls and wall-clock seconds per fork (Zero-Replay Debugging's O(T x |F| x N) cost model), Bytes per fork

**Experiment:** Workflow: one 10-12 step tool-using task (read a local corpus, compute figures, write a summary) implemented twice with identical prompts and tool code: as ActiveGraph behaviors and as a LangGraph graph with SqliteSaver; a shared step index is asserted equal on clean runs. Two tool regimes: stateless (pure functions) and stateful (a scratch SQLite table the run writes early and reads later). Ground truth: 40 single-point faults per regime by replay-then-inject (fork at step k, corrupt one tool or model response, continue to failure). For each fault, three forks carrying the same correction at k: (a) ActiveGraph fork (cached prefix); (b) LangGraph update_state fork (re-fires the suffix); (c) LangGraph fork plus restore of the SQLite file at k. Record whether the outcome flips (K = 3 corrections, as in CausalFlow), first-divergent-action index and edit distance of the untouched suffix, model calls, seconds, bytes; also one unguided rerun per fault (SymTrace baseline). Repeats: 3 at temperature 0, 1 at 0.7. Runs: 40 x 2 regimes x 3 forks x 4 repeats = about 960 forks, ~6 calls each = about 6,000 mini-model calls, plus 320 reruns.

**Novelty:** The Replay Gap measures suffix divergence after swapping models on a logged trajectory but has no checkpoint arm; Repair or Resample (SymTrace) compares prefix replay to unguided reruns without varying the record substrate; DoVer, Causal Agent Replay and CausalFlow define intervention-based attribution but are substrate-agnostic and CausalFlow even replaces real re-execution with LLM-predicted outcomes for non-code tasks; ACRFence and Safe to Resume show that checkpoint re-execution mishandles side effects, but frame it as a security problem, not an audit one; Crab scores recovery correctness on its chat-only / chat+FS / full-state ladder, not counterfactual verdicts. No paper puts a cached-prefix fork and a re-fire fork on identical injected faults, and none crosses fork type with tool statefulness. ActiveGraph's central claim, that its forks are 'cheap and honest', has never been measured; this experiment is the missing test and also fills the checkpoint-family gap in the attribution literature.

## H11: One missing field: redaction level times architecture decides which policies stay checkable

## H12: Can a claim-to-evidence graph be rebuilt after the fact? Testing 'post-hoc verification cannot recover reasoning chains'

**Statement:** A claim-to-source evidence graph rebuilt after the run from the event log alone recovers at least 80% of the support edges that an inline overlay captured during writing when each piece of evidence entered the run through its own tool call, but under 50% when several sources were read and combined inside one model call - so Rasheed et al.'s claim that post-hoc verification cannot recover reasoning chains holds only for within-call reasoning, and log-primary lineage suffices whenever the workflow forces evidence through tools.

**Prediction:** Confirmed if post-hoc edge recall against the human-checked inline ground truth is at least 80% in the tool-mediated mode and at most 50% in the synthesis mode, PCov follows the same split, and verification cost per claim (judge tokens and seconds) is well below generation cost for both overlays but not for a judge working from the raw log (so E_verify << E_generate holds for overlays only). ## H13: Cheap forks are only honest if the world is rebuilt (counterfactual validity vs. recovery boundary)

**Statement:** On one tool-using workflow, forking a run at step k with one change (a counterfactual) repairs injected faults equally well under log-primary, checkpoint and overlay records while tools are stateless, but as soon as steps before k have written to external state (a scratch file or memory store), forks from graph-state-only checkpoints and from span caches repair fewer faults and diverge earlier than forks from an event log that rebuilds that state, with the gap growing with the number of such writes.

**Prediction:** CONFIRMED if: (a) in the stateless variant, the repair ('flip') rate and the first-divergent-action index are statistically indistinguishable across the four substrates, within the noise of same-decision control forks (Replay Gap reports 6-35% first-action divergence even with no change); (b) in the stateful variant, the flip rate of graph-state-checkpoint forks and span-cache forks falls, and their first-divergent index moves earlier, monotonically with the number of external writes before k, while log forks and checkpoint+file-snapshot forks stay flat; (c) log forks use the fewest model calls per fork because the shared prefix is served from cache. REFUTED if checkpoint-only forks match log forks in the stateful variant (graph state is enough), or if log forks degrade too because re-applying recorded write events does not actually rebuild the state the later steps read, or if control noise is so large that no substrate difference exceeds it.

**Architectures:** log-primary: JSONL event log with a hash-keyed (content-addressed) cache of every model/tool response, where the scratch store is rebuilt by re-applying recorded write events during replay (ActiveGraph-style; ActiveGraph itself can be used if the workflow is ported), checkpoint-based: LangGraph SqliteSaver checkpoint per superstep, forked via update_state()/invoke(None); variant C+E adds a copy of the external scratch file at each checkpoint (the Crab 'chat+FS' rung), provenance-overlay: OpenInference/OTel spans in SQLite with an agent-timetravel-style fork that replays cached span responses up to k and goes live after

**Audit tasks:** counterfactual analysis, failure localization (replay-verified attribution: does fixing step k flip the outcome?), execution reconstruction (prefix fidelity as a by-product)

**Metrics:** flip / repair rate per fault (DoVer, CausalFlow CRS), first-divergent-action index and normalized post-fork action edit distance (The Replay Gap), prefix-replay validity fraction / replay fidelity F (The Replay Gap; agrepl), model calls and seconds per fork (cost model from Zero-Replay Debugging), count of SF3 external-state-mismatch and SF5 unrecorded-effect incidents (Safe to Resume?), same-decision control divergence rate (noise floor)

## H15: Hash it and you cannot check it: policy decidability and privacy across the three records

**Statement:** Applying privacy-preserving recording (field-level redaction, or hash-only payloads) to the same runs lowers the share of structural policies that remain decidable from the record (SPDR) in an architecture-specific order: the provenance overlay keeps the most policies decidable and the highest evidence-tracing coverage, the event log keeps every ordering and approval policy but loses content policies, and per-step checkpoints lose content policies and, in addition, the ability to replay or fork, while saving the least storage because personal data is repeated in every snapshot.

**Prediction:** CONFIRMED if: (a) on raw records SPDR is ~1.0 for all three; (b) at hash-only level all content policies become undecidable in all three (Proposition 1 holds empirically) while ordering/approval policies stay decidable in the log and overlay, and lineage policies ('every cited source was fetched') stay decidable only in the overlay because its edges survive hashing; (c) a fork/replay from the redacted checkpoint store fails or produces a different state (RF < 1) while the log still replays structure; (d) bytes saved by redaction are smallest for checkpoints because the same personal data was stored once per snapshot. REFUTED if SPDR degrades identically across architectures (the schema alone decides, architecture is irrelevant), if checkpoints keep replay working after redaction, or if the overlay loses lineage decidability once payloads are hashed.

**Architectures:** log-primary: JSONL event log with optional SHA-256 hash chain (Agent Flight Recorder / AuditWeave style), with three privacy levels: raw, field-redacted, hash-only (IETF Agent Audit Trail draft schema), checkpoint-based: LangGraph SqliteSaver per-step checkpoints with a custom serializer that applies the same redaction/hashing to every snapshot, provenance-overlay: inline W3C PROV graph (entities/activities/edges) with payloads raw, redacted, or hashed, plus ProvAbs-style grouping of sensitive sub-graphs as the overlay's native redaction operator

**Audit tasks:** policy compliance checking, evidence tracing, execution reconstruction, evidence integrity (verification of hash chain after redaction), counterfactual analysis (does a fork from the redacted record still run?)

**Metrics:** SPDR (structural policy decidability rate) and ADL (Auditable Agents), RF and ACR (record fidelity, action coverage; Auditable Agents), PCov (AAR provenance coverage) under each privacy level, IS integrity level and VC verification cost (Auditable Agents), surviving-PII count and verifier-field retention (RedAct-style), bytes per step per record and per privacy level, fork/replay success from the redacted record (yes/no; RF of rebuilt state)

## H16: Snapshot interval is the dial between log and checkpoint (storage vs. exact rebuild cost)

**Statement:** For the same agent run, the append-only event log with cached model and tool outputs is the cheapest record that rebuilds the state at any step exactly: per-step full-state checkpoints cost several times more storage because every snapshot repeats the whole message history, checkpoints taken every n>1 steps save storage only by re-executing model calls between snapshots (which costs money and returns a different state), and an OTel-style span overlay either stores about as much as the log (payloads kept) or cannot rebuild state at all (payloads hashed).

**Prediction:** CONFIRMED if: (a) checkpoint bytes vs. step count fits a quadratic and log bytes a linear curve, with per-step checkpoint storage >= 3x the log at 25 steps and >= 5x at 50 steps; (b) rebuilding state at step k from the log is exact (RF = 1, byte-identical) at all k, while for interval n>1 the rebuilt state at non-snapshot steps has RF < 1 in a non-trivial fraction of cases (re-executed model calls differ) and costs model calls and dollars; (c) the payload-carrying span overlay is within 1.5x of the log in bytes, and the hash-only overlay cannot rebuild state (RF near 0) but answers lineage queries; (d) the measured storage-plus-rebuild-cost minimum over n lies within 2x of the Young/Daly interval sqrt(2*mu*C). REFUTED if checkpoint storage is within 1.5x of the log (incremental channel storage makes it linear), if re-execution at temperature 0 reproduces the original state almost always (so interval n>1 loses nothing), or if fold time from the log is so small at all tested lengths that no compute trade-off exists at term-paper scale.

**Architectures:** log-primary: JSONL event log plus hash-keyed response cache (raw and gzip); state at k obtained by folding the first k events with cached responses, checkpoint-based: LangGraph SqliteSaver wrapped to keep every n-th checkpoint, n in {1, 2, 4, 8, 16}; state at k obtained by loading the nearest checkpoint <= k and re-executing the missing steps live (as LangGraph time-travel does); a variant that also caches responses is the log/checkpoint hybrid (Lineage Stash-style), provenance-overlay: OpenInference/OTel spans exported to SQLite, once with full input/output payloads and once with payload hashes only; answers lineage and ordering queries but does not restore state

**Audit tasks:** execution reconstruction, evidence tracing (lineage queries answerable without replay), counterfactual analysis (cost of rewinding to step k as the prerequisite for a fork)

**Metrics:** bytes per run and per step for each record (raw and gzip); fitted growth exponent (linear vs. quadratic), RF and ACR of the rebuilt state vs. ground truth (Auditable Agents); byte-identical yes/no, replay fidelity F (agrepl) and prefix-replay validity fraction (The Replay Gap), milliseconds, model calls and dollars to rebuild step k, Young/Daly optimal interval sqrt(2*mu*C) vs. measured optimum, implementation-complexity proxy: lines of code and number of integration points per recorder, recovery-correctness ladder (state only vs. state + scratch file), as in Crab

**Experiment:** Same workflow at three length tiers (~10, 25, 50 steps), 30 tasks each, temperature 0. Record every run with: (L) JSONL event log plus hash-keyed response cache (raw and gzip); (C_n) LangGraph SqliteSaver wrapped to keep every n-th checkpoint, n in {1, 2, 4, 8, 16}; (O) OpenInference spans, once with payloads and once with payload hashes only. The n = 1 checkpoint sequence is the ground truth for 'state at step k'. For each run and each k at 25/50/75/100% of steps, rebuild state at k from each record: log -> fold events, serving responses from cache; C_n -> load nearest checkpoint <= k and re-execute the missing steps live; O -> answer lineage queries only. Compare with ground truth: RF and ACR (field-level match), byte-identical yes/no, plus milliseconds, model calls and dollars per rebuild. Fit bytes vs. steps per record (linear vs. quadratic) and report bytes per step; count lines of code and integration points per recorder. Compute the Young/Daly interval sqrt(2*mu*C) with C = checkpoint cost (bytes or ms) and mu = average steps between audit requests (sampled uniformly), and compare with the measured minimum of storage + rebuild cost. About 90 base runs and roughly 5,000 re-execution model calls; a few dollars.

## H17: Bigger record, fewer decidable policies: Proposition 1 as the mechanism behind architecture differences in ACR/RF/LPC/SPDR/IS

**Statement:** When one and the same agent run is recorded by a per-step checkpointer, an append-only event log, and a span-based provenance overlay, the checkpoint record will be the largest in bytes yet score lowest on Lifecycle Coverage (LPC) and Structural Policy Decidability Rate (SPDR), and every policy that is undecidable from a given record will be traceable to one named field that that record's schema does not store (the mechanism stated as Proposition 1 in 'Auditable Agents').

**Prediction:** Confirmed if: (i) LPC and SPDR are ordered event log >= overlay > checkpoint, with LPC gaps of at least 0.2 and at least 3 of 20 policies decidable from the log but undecidable from the checkpoint; (ii) bytes per step are ordered checkpoint > overlay >= log, so record size and decidability are anti-correlated; (iii) at least 90% of undecidable verdicts name a single missing field, and adding just that field to the recorder flips the verdict to comply/violate; (iv) Evidence Integrity scores IS=2 (hash-chained) for the log and IS<=1 for checkpoint and overlay, with the tamper test detected only on the log. Refuted if the checkpoint reaches SPDR >= the log's, if undecidable verdicts persist after the named field is added (decidability is not schema-driven), or if the log is the largest record.

**Architectures:** Checkpoint-based (LangGraph SqliteSaver, full-state snapshot per superstep), Log-primary (hash-chained append-only JSONL event log, Agent Flight Recorder eight-field schema), Provenance overlay (OpenInference/OTel GenAI spans + PROV-DM entities)

**Audit tasks:** Execution reconstruction, Policy compliance checking, Decision review / responsibility attribution, Evidence integrity

**Metrics:** ACR (Action Coverage Rate) and RF (Record Fidelity) from Auditable Agents, LPC (Lifecycle Phase Coverage) and GB (Gap Burden) from Auditable Agents, SPDR (Structural Policy Decidability Rate) and ADL (Audit Detection Latency) from Auditable Agents, AC / ACD (responsibility chain coverage and depth) from Auditable Agents, IS ordinal 0-3 and VC (verification cost) from Auditable Agents, Bytes per step and per-step latency (cost axis; compare to Agent Flight Recorder's 512 B/event and Aegis's 8.3 ms)

## H18: Record architecture, not just record length, changes step-level failure-localization accuracy for a fixed LLM auditor

**Statement:** Given the same LLM auditor, the same token budget and the same injected faults, step-level failure-localization accuracy depends on which architecture produced the record: a runtime provenance overlay with data-dependency edges beats the flat event log on faults where a wrong input was used, per-step checkpoint state diffs beat both on faults where a tool result was silently corrupted, and the overlay's advantage over the log grows with run length.

**Prediction:** Confirmed if there is a format-by-fault-type interaction: on dependency faults (wrong source used) the overlay exceeds the log by at least 10 points of step exact-match; on state-corruption faults checkpoint diffs match or exceed the log; and the overlay-minus-log gap is larger on 60-step runs than on 25-step runs at the same token budget, while the position-only and shuffled-label controls stay near chance. Refuted if all three records are within confidence intervals at both lengths and both budgets (only length matters), if the flat log wins on every fault type, or if the apparent gains disappear under the artifact controls (the judge was reading injection traces, not the record).

**Architectures:** Log-primary (append-only event log serialized in order), Checkpoint-based (LangGraph checkpoint sequence rendered as state diffs between snapshots), Provenance overlay (OTel spans plus runtime-captured data-dependency edges from the tool wrapper)

**Audit tasks:** Failure localization

**Metrics:** Step-level exact-match accuracy and agent-level accuracy (Who&When), Root-cause +/-k tolerance accuracy (LongRCA Bench, here +/-2), Location accuracy / joint accuracy (TRAIL style), Tokens per audit (compute axis) and bytes per record (storage axis), Bootstrap 95% confidence intervals; position-only and shuffled-label baselines (CatchBench guardrail)

**Experiment:** Workflow: the H1 agent plus a longer variant (about 60 steps). Recording: the same run captured as event log, checkpoint sequence (state diffs between snapshots), and runtime overlay (OTel spans plus data-dependency edges recorded by the tool wrapper: which earlier output each call consumed). Auditor: one fixed LLM judge, same prompt skeleton, each record serialized to text under a fixed token budget (4k and 16k), two Who&When protocols (all-at-once, step-by-step). Measurements: step exact-match, +/-2 tolerance (LongRCA style), agent-level accuracy, tokens per audit, bytes per record, bootstrap 95% CIs. ## H19: Three ways to ask 'what if step k had been right': cached-log fork vs checkpoint restore vs simulated counterfactual on a fidelity-versus-cost curve

**Statement:** For the same injected fault at step k, a counterfactual re-run from a log-primary record with a content-addressed response cache will recover the clean outcome as often as a checkpoint restore when tools are stateless, will beat it by a wide margin when tools mutate external state, and will cost only the suffix (T minus k) model calls, whereas a 'simulated' counterfactual computed by an LLM over the provenance overlay without re-execution will cost almost nothing but its accuracy will fall as (T minus k) grows.

**Prediction:** Confirmed if: with stateless tools the log fork and the checkpoint fork have counterfactual recovery rates within 5 points of each other and both exceed the simulated arm by at least 20 points; with stateful tools the log fork exceeds the plain checkpoint fork by at least 20 points and the checkpoint+env variant closes most of that gap; model calls per fork are about (T-k) for both observed arms and about 1 for the simulated arm; and the simulated arm's accuracy has a clearly negative slope in (T-k). Refuted if the plain checkpoint recovers as well as the log with stateful tools (unrestored side effects do not matter), if the simulated counterfactual matches the observed forks at all distances, or if the cached prefix fails to reproduce the original failure (reproduction rate below 0.9), which would undercut the log's claimed determinism.

**Architectures:** Log-primary (content-addressed cache of model/tool responses keyed by request hash; ActiveGraph / AgentCheck style cached-prefix fork), Checkpoint-based (LangGraph get_state_history + update_state + invoke, with and without a per-step environment snapshot), Provenance overlay (dependency graph used for a no-re-execution simulated counterfactual, CHIEF style)

**Audit tasks:** Counterfactual analysis, Failure localization (verifying a suspected step by whether fixing it flips the outcome)

**Metrics:** Counterfactual recovery rate (fork outcome equals clean-run outcome; CausalFlow's Causal Responsibility Score in the single-alternative case), Failure-reproduction rate of the untouched prefix (SymTrace, 'Repair or Resample?'), First-divergent-action index and prefix-match replay-validity fraction ('The Replay Gap'), Replay fidelity F (agrepl, 'Deterministic Replay for AI Agent Systems'), Model calls and wall-clock per fork (cost model from 'Knowledge-Based Zero-Replay Debugging'), Extra bytes per fork branch (storage axis)

What is new: the first side-by-side fidelity-versus-cost curve of the three counterfactual regimes on identical faults, with tool statefulness as the moderator that predicts where the checkpoint family breaks and the checkpoint+env hybrid as the repair, plus a direct test of whether the log's determinism contract survives a real model endpoint.

## H20: Claim-to-evidence tracing: observed edges from an inline overlay vs inferred links from the log vs whatever survives compaction in a checkpoint, measured with PCov/PSnd/AEff

**Statement:** On the same research-agent run, claims can be traced to supporting sources with higher Provenance Coverage (PCov), higher Provenance Soundness (PSnd) and shorter audit paths (AEff) from an inline claim-evidence overlay than from the event log or the checkpoint store, because the overlay records the claim-to-source link as an observed edge during synthesis, whereas the log forces the auditor to infer that link afterwards (costing about one extra model call per claim and yielding lower-soundness links) and the checkpoint store has already dropped the retrieved passages that a compaction step summarized away.

**Prediction:** Confirmed if: PCov from the overlay is at least 0.95, PCov from the log reaches the same level only after a reconstruction pass of at least one model call per claim, and PCov from the checkpoint is the lowest and its orphaned claims are exactly those whose passages were compacted; PSnd of observed edges exceeds PSnd of declared or inferred edges by at least 10 points on the hand-labelled subset; planted 'citation laundering' faults are caught by the overlay (observed edge disagrees with declared citation) at a much higher rate than by the log or checkpoint; and AEff path length is shortest for the overlay. Refuted if the log's reconstruction matches the overlay's PCov and PSnd at zero extra model calls, if the checkpoint's PCov is about equal to the log's (compaction loses nothing that matters), or if observed edges are no sounder than declared ones.
